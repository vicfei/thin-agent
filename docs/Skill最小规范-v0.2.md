# Skill 最小规范 v0.2

> 一份文件约定：让"薄内核 agent"不装插件系统就能装载能力。
> 内核的唯一义务：扫描、探测、索引、注入。除此之外，内核不认识 skill。
>
> v0.2 变更（相对 v0.1，全部为加法）：
> ① 新增项目指令文件约定（§6 AGENT.md）；② 新增持久记忆约定（§7 memory.md）；
> ③ 新增上下文压缩约定（§8）；④ 新增会话与审计文件布局（§9）；⑤ 新增虚拟命令
> `agent-done`（§10）；⑥ frontmatter 列表统一为行内写法（§2.1）；⑦ 附参考实现清单（§11）。

---

## 0. 设计原则

1. **约定优于接口**：skill 不实现任何 API、不注册任何回调，只遵守目录与文件约定。
2. **纯文本可审计**：skill 的全部内容必须能以文本形式通过安全评审，禁止可执行二进制。
3. **环境零假设**：只假设 Linux bash 与 python3 存在；其余能力一律经 `requires` 声明并由内核探测。
4. **渐进式披露**：常态下内核只加载索引（name + description），正文与参考资料由模型按需读取，不进系统提示。
5. **前向兼容**：内核**必须**忽略未知字段；本规范的演进只做加法。

## 1. 目录结构

```
skills/
└── <name>/            # 技能目录，kebab-case，全库唯一
    ├── SKILL.md       # 必需。指令清单（frontmatter + 正文）
    ├── scripts/       # 可选。脚本（bash / python3）
    ├── references/    # 可选。按需加载的长文档
    └── assets/        # 可选。模板、数据等输入文件（非代码）
```

- 目录名即技能名：小写字母、数字、连字符，匹配 `^[a-z0-9][a-z0-9-]*$`。
- 内核**必须**忽略不符合命名规则的目录（记入审计日志），不得中断扫描。
- 分发方式即拷贝目录（scp / git clone / u 盘），无安装步骤。
- 技能搜索路径（内核按序合并、按 name 去重，先见优先）：
  `AGENT_SKILLS_DIR` 环境变量（可多目录，冒号分隔）→ `./skills` →
  `agent.py 同级 skills/` → `~/.agent/skills`。

## 2. SKILL.md

YAML frontmatter + Markdown 正文。

### 2.1 frontmatter

| 字段 | 必需性 | 说明 |
|---|---|---|
| `name` | 必须 | 与目录名一致；不一致时该 skill 无效并记日志 |
| `description` | 必须 | 一两句话，写给模型看：**做什么 + 何时触发**。它是唯一常驻上下文的路由信息 |
| `requires` | 可选 | 环境依赖声明，见 §3 |
| `metadata` | 可选 | 自由键值（owner、评审单号等），内核不解释 |
| `service` / `schema` | 保留 | 预留给"长驻服务"与"参数强校验"的扩展，内核**必须忽略** |

- `description` 建议 ≤ 200 字符，且**必须**包含触发条件（"当……时使用"）。
- **列表统一使用行内写法**（v0.2 明确）：`bins: [jq, ffmpeg]`。受限环境没有 YAML
  解析器，内核只实现"key: value / 嵌套一层 / 行内列表"的子集，故不写缩进式列表。
- 未知字段一律忽略，不得报错。

示例：

```yaml
---
name: csv-stats
description: 快速了解 CSV 文件的结构与数据质量（行数、缺失、唯一值、数值范围）。当用户给出 CSV 并希望"看看里面有什么 / 数据质量如何"时使用。
requires:
  python: ">=3.6"
metadata:
  owner: data-platform
  review: SEC-2026-0000
---
```

### 2.2 正文（Markdown）

正文是写给模型的操作手册，**必须**覆盖：

- 何时使用、何时**不**使用（边界）；
- 每个脚本的调用命令行与参数说明；
- 输出格式说明（模型如何解读结果）；
- 常见失败与处理方式。

约定：

- 引用本技能内的文件一律使用 `{SKILL_DIR}` 占位符；内核在提供文件内容时将其替换为该技能目录的**绝对路径**。
- 不假设工作目录；所有路径以 `{SKILL_DIR}` 展开后的绝对路径为准（内核动作无状态，`cd` 不跨步保留）。
- 正文建议 ≤ 500 行；超出部分拆入 `references/`，正文给出文件清单，模型按需读取。

## 3. requires：能力协商

```yaml
requires:
  bins: [jq, ffmpeg]     # 必须存在于 PATH 的命令（行内列表）
  python: ">=3.6"        # 对 python3 的版本要求（可选；支持 >= <= == > <）
  env: [FOO_API_KEY]     # 必须已设置的环境变量（可选）
```

探测规则（内核行为，规范性）：

1. 扫描阶段对每个 skill 执行探测：`command -v` 检查 `bins`；比对 python 版本；检查环境变量存在性。
2. 探测失败的 skill **不进入索引**，失败原因记入审计日志。
3. 探测只在启动时执行一次。模型默认感知不到被过滤的 skill（调试时可通过 `/skills` 与审计日志查询）。

这一条消灭了"模型调起不存在的工具"这一类错误：装不了的技能，模型根本看不见。

## 4. 脚本约定

- **显式解释器调用，不依赖可执行位**：`python3 {SKILL_DIR}/scripts/foo.py`、`bash {SKILL_DIR}/scripts/foo.sh`（受限挂载可能不支持 exec bit）。
- Python 脚本默认仅用标准库，**语法地板 3.6**（不用 walrus / match / dataclass）；确需第三方包时，必须是纯 Python 并 vendor 到技能目录内（如 `vendor/`），由脚本自行 `sys.path.insert`。**禁止二进制扩展**。
- 非交互：参数经 argv 传入；不得从 stdin 等待输入。
- 退出码：0 为成功；非 0 为失败，原因写 stderr。
- **上下文经济**：stdout 只输出精炼结果（结构化结果用 JSON，schema 在 SKILL.md 中说明）；大体量结果写入文件，stdout 只打印"路径 + 摘要"。确定性处理下沉到脚本，模型只做编排与解读。
- 超时：脚本须在内核命令超时（默认 120s）内完成；长任务应拆步执行或写进度文件。常驻能力不属于本规范，走保留字段 `service`。

## 5. 内核加载流程（规范性）

1. 扫描技能搜索路径，解析 frontmatter；坏目录、坏 frontmatter、`name` 不匹配一律忽略并记日志，不得中断。
2. 执行 `requires` 探测，过滤不可用 skill。
3. 在系统提示中注入索引，每条一行：`- <name>: <description>`。
4. 模型用 `read_file` 读取 SKILL.md 正文或 references；内核返回内容前替换 `{SKILL_DIR}`。
5. 模型用 `bash` 调起脚本。权限闸门、超时、输出截断、审计日志是内核职责，不属于本规范；skill **不得**要求以后台 / nohup 等方式脱离审计。

> 规模说明：索引在 ~50 条以内时全量注入即可。超过后，内核可把"检索技能"暴露为工具，让模型自行 grep `skills/*/SKILL.md`——这仍不违反本规范，内核无需引入向量索引。

## 6. 项目指令文件：AGENT.md（v0.2 新增）

能力与项目上下文分离：skills 管"能做什么"，AGENT.md 管"这个项目里该怎么做"。

- 内核启动时按序加载：`~/.agent/AGENT.md`（全局层）→ 自根目录到 cwd 逐级的
  `AGENT.md` 或 `AGENTS.md`（项目层，就近优先、后者覆盖前者的语义由模型自行调和）。
- 每份注入前截断至 4000 字符；全文仍可被模型用 `read_file` 按需读取。
- 内容为纯 Markdown：项目背景、目录约定、命令基线、禁止事项。不写密钥。

## 7. 持久记忆：memory.md（v0.2 新增）

- 路径固定为 `<cwd>/.agent/memory.md`；存在则注入系统提示（截断 4000 字符）。
- **写入与更新必须走普通 bash 工具**——即过闸门、留审计；内核不提供任何旁路写接口。
- 用途：跨会话记住项目事实与教训（如"这台机器的 vLLM 在 8000 端口"）。它是压缩之外的第二上下文机制：压缩丢细节，memory 存要点。

## 8. 上下文压缩（v0.2 新增）

- 触发：投影消息体积超过 `AGENT_COMPACT_CHARS`（默认 60000 字符）时，内核在下次模型调用前自动压缩。
- 方式：把早期历史（保留最近 6 条之外的部分）发给模型做摘要；**prompt 默认内置，可被 `<cwd>/.agent/compact.md` 整体覆盖**——压缩策略是文本约定，不是内核代码。
- 留痕：压缩生成 `compact` 事件写入会话日志；投影在遇到最近的 `compact` 边界时停止回溯。早期历史不删除，仍可审计回放。
- 手动触发：交互模式 `/compact`。

## 9. 会话与审计文件布局（v0.2 新增）

```
<cwd>/.agent/
├── sessions/<hash(cwd+用户名)>.jsonl   # 目录级会话：append-only 事件日志，唯一事实源
├── audit.jsonl                         # 全局审计：闸门决策 / 技能加载 / 压缩 / 启停，一行一条
├── memory.md                           # 持久记忆（见 §7）
└── compact.md                          # 可选：压缩 prompt 覆盖（见 §8）
```

- 会话按 `cwd + 用户名` 哈希定位：同目录同用户启动自动延续；多用户共用目录不串会话。
- 事件携带 `parent` 指针构成树；`/clear` 追加边界事件开启新分支，历史不删除。
- 喂给模型的消息 = 从 head 沿 parent 回溯到最近边界的纯函数投影；"模型看到的"与"日志记录的"因此恒等。

## 10. 虚拟命令 agent-done（v0.2 新增）

- 目标模式（`-g`）的终止哨兵：模型执行 `agent-done <一句话总结>`，内核在闸门**之前**拦截，不进入 shell，目标循环结束。
- 这是规范级的保留命令名；skill 脚本不得使用同名命令。

## 11. 参考实现（v0.2 新增）

`agent.py`（单文件、零依赖、Python 3.6+）是本规范的参考内核，实现清单：

## 12. 非目标（明确不做）

- 版本解析与依赖求解（版本号只作为 `metadata` 供审计）；
- 远程分发与包管理；
- 插件注册表、生命周期管理、热加载、卸载；
- 参数强校验（保留字段 `schema`）；
- 长驻服务（保留字段 `service`）；
- agent 运行时自我改造。

踩到这些需求时，为单个问题引入最小机制，而不是把本规范升级成插件框架。

## 14. 兼容与演进

- 本版本为 v0.2，演进只做加法；v0.2 内核兼容全部 v0.1 技能。
- 内核**必须**忽略未知 frontmatter 字段与目录内的未知条目——这是 skill 与内核各自独立演进的前提。
- 判断一个特性该不该进规范的标准：去掉它，skill 还能不能跑？能，就不进。
